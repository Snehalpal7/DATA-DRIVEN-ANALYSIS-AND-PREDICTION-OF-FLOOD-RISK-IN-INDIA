# India Flood Risk Intelligence

A complete Python analytics and Streamlit dashboard project for `India_Flood_Inventory_v3.csv`. It performs data-quality inspection, cleaning, feature engineering, exploratory analysis, association analysis, model comparison, explainable impact-risk estimation, and SDG 13-oriented decision support.

## Important dataset interpretation

This CSV is a historical flood-event inventory with 6,876 rows and 23 source columns. It is **not** a row-level climate sensor dataset. The source contains no populated rainfall, temperature, humidity, water-level, latitude, longitude, or severity measurements. The project therefore does not invent those KPIs or claim that they were measured.

The modeled target is `impact_event`: whether at least one of the recorded human fatality, human injured, human displaced, or animal fatality fields contains a positive numeric value. These outcome fields are excluded from model predictors. The model estimates the probability of a future inventory-style event having a recorded impact; it is not a physical flood forecast and not a guaranteed warning.

## Run locally

```powershell
python -m venv .venv
.\.venv\Scripts\Activate.ps1
pip install -r requirements.txt
python src/flood_analysis.py
streamlit run app.py
```

The dashboard opens at the local Streamlit URL shown in the terminal. The first analysis run creates `outputs/` artifacts; those files are ignored by Git and can be regenerated.

## Analysis workflow

1. Reads and profiles dtypes, missing values, invalid dates, exact duplicates, numeric distributions, and fully missing fields.
2. Parses dates and mixed numeric fields, preserving source values while creating clean numeric features.
3. Adds year, month, season, duration, district count, state count, normalized cause, rain-related wording, and extreme-weather wording flags.
4. Creates the operational impact target from recorded impact fields without using those outcome fields as predictors.
5. Compares Logistic Regression, Decision Tree, Random Forest, and Gradient Boosting with a stratified 80/20 split and five-fold ROC-AUC cross-validation.
6. Reports accuracy, precision, recall, F1, ROC-AUC, cross-validated ROC-AUC, confusion matrix, and false-negative rate.
7. Saves model artifacts and serves interactive Plotly charts through Streamlit.

## Dashboard sections

The dashboard includes overview KPIs, data-quality analysis, annual and seasonal trends, observed risk-band distribution, duration box plots, text-based rain relationship, correlation heatmap, model comparison, confusion matrix, ROC curve, actual-versus-predicted probability chart, feature importance, regional analysis, prediction input form, automatically generated insights, decision-support recommendations, potential impact, and SDG 13: Climate Action alignment.

The requested rainfall, temperature, humidity, and water/river-level KPIs are explicitly marked unavailable because those variables are absent or fully missing in the source. The available rainfall-related analysis is a text-mention indicator derived from event cause/description, not rainfall intensity.

## SDG 13: Climate Action

The project describes a **potential contribution** toward SDG 13 through historical climate-risk awareness, flood-impact analysis, preparedness support, and explainable data-driven decision-making. It can help users inspect event timing, regional representation, recorded impacts, and conditions mentioned in event descriptions. It does not claim to achieve SDG 13, measure climate change, establish causation, or replace official hydrometeorological and emergency-management systems.

Potential users include communities, planners, disaster-management teams, researchers, and relevant authorities. Any operational decision should combine this historical model with live rainfall and river gauges, forecasts, exposure and vulnerability data, local knowledge, and official warning procedures.

## Limitations

- The inventory is event-based, so it lacks non-flood control observations for a physical flood/no-flood classifier.
- The impact target depends on whether consequences were recorded; missing values can mean unknown rather than zero.
- Cause, state, district, and description fields contain inconsistent spelling, capitalization, aggregation, and reporting detail.
- The dataset has fully missing location, coordinates, severity, area, and source-ID fields, so spatial mapping and measured water/rainfall analysis are not possible from this file alone.
- A random split can be optimistic when historical events are temporally or regionally dependent. The displayed results are not guarantees of future performance.
- Correlation and model feature importance indicate association or predictive utility, not causation.
